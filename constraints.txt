# Dependency constraints (#916 / #863)
#
# 役割分担:
#   pyproject.toml  = 外部に対する互換範囲の宣言 (公開契約)。PyPI から install
#                     する第三者が満たすべき範囲。
#   constraints.txt = **この repo 自身の再現環境** の exact pin。CI / ローカル /
#                     Portable ZIP build の 3 者を同一版に揃えるためだけに使う。
#   -> 両者を矛盾させないこと。constraints の値は必ず pyproject の範囲内にする。
#      (矛盾すると pip は ResolutionImpossible で落ち、
#       "The user requested (constraint) ..." という読みにくい形で報告される)
#
# 使い方:
#   pip install -e ".[dev]" -c constraints.txt
#
# pip の性質 (前提として理解しておくこと):
#   - constraints は「どの版を入れるか」だけを決め、install はトリガーしない。
#     依存グラフに現れない名前を書いても pip は **無言で無視する**
#     (unused constraint を検出するコードパスが pip に存在しない)。
#     = pin が朽ちても CI は緑のまま。
#     -> tests/test_dependency_pins.py が「各 == 行が実際にその版で解決されたか」
#        を検査する。行を足したら必ずこのテストが赤 -> 緑になることを確認すること。
#   - editable / extras 付き / 名前なしの行は書けない (InstallationError)。
#     本プロジェクト自身 (kobutachan-allaganeye) を書いてはいけない。
#   - `-c` は PEP 517 の分離ビルド環境に伝播しない。したがって
#     [build-system] requires の setuptools は本ファイルでは固定できない
#     (#916 の既知の残余。docs/l2-workflow.md §外部依存規約 参照)。
#   - 本ファイルには `name==version` だけを書く。範囲行は pin として機能せず、
#     tests/test_dependency_pins.py の検査対象からも静かに外れる。
#
# ここに書かないもの (理由):
#   - ruff / pyright  : pyproject.toml の dev extras が exact pin の SSoT (#907)。
#                       重複させると片方だけ bump したとき解決不能になる。
#   - typer / click   : pyproject.toml の <0.25 / <8.4 が事実上 exact (#863)。
#   - kobutachan-allaganeye 自身 : constraint 化すると `-e .` の解決に当たりうる。
#
# bump 手順: docs/developer-setup.md §9 「依存 constraints の bump 手順」
