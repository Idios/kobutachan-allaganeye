> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development` (fresh subagent per task + spec/quality 2-stage review). TDD HARD-GATE (`superpowers:test-driven-development`): NO PRODUCTION CODE WITHOUT A FAILING TEST FIRST. Steps use checkbox (`- [ ]`).

**Goal:** PreviewScreen で OUT < IN (`end_time <= start_time`) の境界を**無検証で apply** でき metadata.json が GUI 自身で読めなくなる (P1-2)、load 失敗が**非表示**で「No metadata」空画面になる (P2-13)、apply 後の `*_display` 文字列が数値と乖離する (P2-17) の 3 件を解消する。

**Architecture (多層防御):**

- **境界 validation (AC1/AC2)**: ① PreviewScreen の境界編集 (nudge / frame step / FrameStrip / TC 入力) に相互クランプを入れ `startT <= endT` を維持、② `[適用]` ボタンを `end > start` でない時 disabled + 理由表示、③ store `runApply` が apply 直前に全 match の `end > start` を強制し違反時は `apply_changes` を invoke せず `applyErrorState` を set、④ Rust `apply_changes_sync` にも同 guard を追加し `validation.boundary_invalid` AppError で返す (write 境界の最終防衛)。**read は寛容 (zod は `end >= start`)、write は厳格 (`end > start`)** に保ち、GUI が書いた値は必ず再読込できる (Postel)。
- **load エラー可視化 (AC3)**: ① DetectingScreen が detect 完了後の `loadMetadata` 失敗 (`loadErrorState` 非 null) を検知し既存の専用 error view (`DetectingErrorView`) へルーティング、② CompleteScreen 空状態が `loadErrorState` を表示、③ `restore()` の reload 失敗を成功扱いせず `restoreErrorState` に転記。
- **display 文字列整合 (AC4)**: `normalizeForPersistence` が `start_display`/`end_display`/`duration_display` を `utils/time.ts` の `fmtTime` / `fmtMatchDuration` で再生成する。両 fn は CLI の `_format_timestamp` (`{h}:{m:02}:{s:02}` / `{m:02}:{s:02}`) / `_format_duration` (`{m}m{ss:02}s` / `{h}h{mm:02}m`) と仕様一致 (`commands/split_matches.py:1732,1757` で確認済)。

**Tech Stack:** React 19 + TS (Vitest/jsdom) / Zustand / zod / Rust (Tauri 2, serde_json) / cargo test。

```rust
    meta_path: &Path,

    expected_mtime_ms: Option<u64>,
) -> Result<(), AppError> {
    // #814 -- reject boundaries the GUI can't read back. The zod MatchSchema
    // refine rejects end_time < start_time on reload, so persisting one would
    // brick metadata.json (audit P1-2). The frontend blocks this at apply time
    // too; this is defense in depth at the write boundary. Strict end > start
    // (AC: end <= start is blocked). Matches missing start_time/end_time are
    // left to the schema on read and skipped here.

                        format!(
                            "match at index {} has end_time ({}) <= start_time ({})",
                            i, end, start
                        ),
                    )
                    .with_default_hint());
                }
            }
        }
```

```ts
/**
 * #814 -- single definition of the metadata match-boundary write invariant.
 *
 * A match must have a strictly positive duration: `end_time > start_time`.
 * The zod MatchSchema refine is lenient on read (`end >= start`), but the GUI
 * must never *write* a degenerate or inverted boundary — `end < start` makes
 * metadata.json unreadable on reload (audit P1-2) and `end == start` produces
 * an empty clip. Used by both `metadataStore.runApply` (apply-time block) and
 * `PreviewScreen` (the [適用] button disable + edit clamp).
 */
export function isBoundaryValid(startTime: number, endTime: number): boolean {
  return (
    Number.isFinite(startTime) &&
    Number.isFinite(endTime) &&
    endTime > startTime
  );
}
```
