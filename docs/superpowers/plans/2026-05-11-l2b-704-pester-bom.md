## Task 2: BOM 付与 (binary file rewrite)

`scripts/tests/build-portable-zip.Tests.ps1` の先頭に `EF BB BF` 3 byte を prepend する。`[System.IO.File]::ReadAllBytes` / `WriteAllBytes` を使い、PowerShell の text encoding 機構を経由しないことで EOL 変換 (LF → CRLF 等) を回避する。

**Files:**

- Modify: `scripts/tests/build-portable-zip.Tests.ps1` (binary, line 1 に 3 byte 追加のみ、内容実体不変)

- [ ] **Step 1: Run BOM prepend 1-liner**

Run (PowerShell 5.1 / 7.x いずれでも可、本 worktree は Windows なので PowerShell 推奨):

```pwsh
pwsh -NoProfile -Command "
$path = 'scripts/tests/build-portable-zip.Tests.ps1'
$bom  = [byte[]](0xEF, 0xBB, 0xBF)
$body = [System.IO.File]::ReadAllBytes($path)
[System.IO.File]::WriteAllBytes($path, $bom + $body)
"
```

`ReadAllBytes` / `WriteAllBytes` は raw byte で読み書きするため、PowerShell の `Set-Content -Encoding utf8BOM` (PS6+ only) や `Out-File` (encoding 暗黙変換) を経由するより安全。EOL bytes (CRLF / LF) は完全保存。

- [ ] **Step 2: Verify BOM prepend succeeded (byte-level)**

Run:

```bash

```

Expected: `00000000: efbb bf3c 230d                            ...<#.` (= `EF BB BF` BOM + `<#\r` 旧先頭)

- [ ] **Step 3: Verify EOL invariance via git diff (no LF↔CRLF conversion)**

Run:


Expected: `1 file changed, 1 insertion(+)` または `1 insertion(+), 1 deletion(-)` の最小 diff。**`100+ insertions/deletions` のような大きい diff が出たら EOL conversion が起きている → STOP** し以下で復旧:

## Task 3: 新 `Describe 'File encoding (#704)'` block 追加 (TDD Red)

**TDD 順序の特殊性:** 通常 TDD は test 先行で red を確認するが、本 task は (a) test の本体が「自身が BOM 付きか」を assert する self-referential check のため、Task 2 で BOM 付与しないと test 自身が parse 失敗する、(b) BOM が無い状態で先に test を append しても PS5.1 では parse error で test discoverable になれない、ため Task 2 → Task 3 の順序が必要。代替として Task 3 で「BOM が剥がれた偽装」を一時的に作り red を確認する手順も含める。

**Files:**

- Modify: `scripts/tests/build-portable-zip.Tests.ps1` (file 末尾、現存最終 `Describe 'GetPip pinning (#681)'` block の閉じ `}` の後に append)

- [ ] **Step 1: file 末尾の現状確認**

Run:

```bash
tail -10 scripts/tests/build-portable-zip.Tests.ps1
```

Expected: `Describe 'GetPip pinning (#681)' { ... }` の閉じ `}` で終わる (line 約 470+ 付近、commit `1e372f1` 時点)。**末尾 byte が改行で終わっているか** も確認 (`tail -c 1 scripts/tests/build-portable-zip.Tests.ps1 | xxd` → `0a` か `0d 0a` で終わるべき)。

- [ ] **Step 2: 新 `Describe` block を append**

Open `scripts/tests/build-portable-zip.Tests.ps1` で file 末尾 (現存最終 `}` の **次行**) に以下を append:

```pwsh

Describe 'File encoding (#704)' {
  It 'is saved as UTF-8 with BOM so PowerShell 5.1 (powershell.exe) can parse non-ASCII comments' {
    # Without a BOM, Windows PowerShell 5.1 (default ANSI / CP932 in JP locale)
    # interprets non-ASCII comments as Shift-JIS, causing parse errors. The CI
    # `installer-pester` job uses `pwsh -NoProfile` (PS7.x, UTF-8 default), so
    # local PS5.1 regression coverage relies on a BOM marker. See #704.
    $bytes = [System.IO.File]::ReadAllBytes($PSCommandPath)
    $bytes[0] | Should -Be 0xEF
    $bytes[1] | Should -Be 0xBB
    $bytes[2] | Should -Be 0xBF
  }
}
```

**先頭の空行** を必ず入れる (前 `Describe` の閉じ `}` 直後に詰めると Pester v5 で `Discover` phase が失敗する稀な edge case 回避、project の既存 `Describe` 間隔と整合)。

`$PSCommandPath` は実行中 Pester test file path を返す自動変数 (PS3+) で、self-referential check として確実。

- [ ] **Step 3: red 確認 (BOM 一時剥がし)**

regression test の有効性を verify するため、BOM を一時剥がして `It` が fail することを確認:

Run (Windows shell):

```pwsh
pwsh -NoProfile -Command "
$path = 'scripts/tests/build-portable-zip.Tests.ps1'
$body = [System.IO.File]::ReadAllBytes($path)
# Strip BOM if present
if ($body[0] -eq 0xEF -and $body[1] -eq 0xBB -and $body[2] -eq 0xBF) {
  $body = $body[3..($body.Length - 1)]
}
$tmp = [System.IO.Path]::GetTempFileName()
[System.IO.File]::WriteAllBytes($tmp, $body)
$result = Invoke-Pester -Path $tmp -FullNameFilter '*File encoding*' -PassThru
Write-Host \"FailedCount: $($result.FailedCount)\"
Remove-Item $tmp
"
```

Expected: `FailedCount: 1` (BOM 剥がし状態で `It` が fail)。**もし `FailedCount: 0` なら test 自体が機能していない** → STOP し test ロジックを再確認。

`FullNameFilter '*File encoding*'` で本 `Describe` block のみ実行し他 test の影響を排除。

- [ ] **Step 4: green 確認 (本物の Tests.ps1 で全 case pass)**

Run:

```pwsh
pwsh -NoProfile -Command "Invoke-Pester -Path scripts/tests/build-portable-zip.Tests.ps1 -PassThru | Select-Object -Property TotalCount, PassedCount, FailedCount"
```

Expected: `TotalCount` = Task 1 Step 4 record値 + 1 (新 case 1 個追加)、`PassedCount` = 同 +1、`FailedCount: 0`。

- [ ] **Step 5: Commit 新 Describe block**

```bash

git commit -m "test(installer): #704 BOM 付与の regression test を追加

Tests.ps1 末尾に Describe 'File encoding (#704)' block を append。
\$PSCommandPath で self-reference し file 先頭 3 byte が EF BB BF (UTF-8 BOM)
であることを assert する。BOM rollback (誤編集での再剥がれ) を防ぐ
regression coverage。
```
