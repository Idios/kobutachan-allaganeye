# Audit Remediation Wave 2 — W2 (#837 GUI export/cancel 安定化) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development` (fresh subagent per task + spec/quality 2-stage review). TDD HARD-GATE (`superpowers:test-driven-development`): NO PRODUCTION CODE WITHOUT A FAILING TEST FIRST. Steps use checkbox (`- [ ]`).

**Goal:** GUI export/cancel ライフサイクルの 5 つの不具合を修正する — (P2-14) cancel 中に export 完了で reducer が永久スタック、(P2-15) `start_export` が stderr を drain せずハング/traceback 喪失、(P2-16) stdout 取得の `expect` が cancel race で panic、(P3-a) ExportScreen の listen() mount race で unlisten leak、(P3-b) ConfirmExitModal の文言が partial file 残置の実態と不一致。

**Architecture:**

- **P2-14 (reducer)**: `exportReducer` の `cancelling` case に `PROGRESS_COMPLETE → completed` 遷移を 1 行追加。cancel 要求後に export が中断前に完了した race では出力ファイルは揃っているため `completed` 表示が正 (現状は `return phase` で `cancelling` に滞留し「中断中…」永久スタック)。pure function。
- **P2-15 / P2-16 (lib.rs `start_export` 再構成)**: stdout/stderr を `track_child` の**前**に `child` から `take()` し (start_detect と同型)、(a) `expect("tracked just inserted")` の post-track lookup を排除 (P2-16)、(b) 取った stderr を bounded tail に drain する `tokio::spawn` task を起こし、非ゼロ exit 時の error に tail を含める (P2-15)。bounded-tail accumulation は新規 pure helper `append_bounded_tail` に切り出して TDD する。**released な `start_detect` の inline drain には触れない** (リスク非対称 = 動作中の detect 経路変更の downside > 軽微な重複の downside。`append_bounded_tail` は新規コードの canonical form として残す)。
- **P3-a (ExportScreen listen leak)**: `export-progress` listen の useEffect に `disposed` フラグを導入。`await listen(...)` 解決時に既に `disposed` なら、取得した unlisten を即時呼んで return (unmount-before-resolve race での leak を解消)。DetectingScreen #813 パターン (memory `feedback_gui_cancel_async_dead_angles` 死角 #2)。
- **P3-b (ConfirmExitModal 文言)**: `kill_tracked_processes` は Job Object hard-kill で Python に SIGINT すら届かず partial .mp4 が残る (graceful SIGINT 経路 `export.py:239` finally も unlink しない)。「(中間ファイルは破棄)」を「(処理中のファイルが未完成のまま残る場合があります)」に訂正 (detect/export 両経路で正確)。

**Tech Stack:** React 19 + TS (Vitest/jsdom, @testing-library/react) / Rust (Tauri 2, tokio::process, tokio::io BufReader) / cargo test。

```rust
/// Append `chunk` to a rolling `tail` buffer, keeping at most ~`max_tail`
/// trailing bytes. Used by start_export's stderr drain so a chatty child can't
/// grow the buffer without bound while still preserving the most recent output
/// for the error message (audit P2-15). Drains only when the buffer exceeds
/// `max_tail * 2`, amortising the shift cost (same shape as start_detect's
/// inline drain loop).
fn append_bounded_tail(tail: &mut Vec<u8>, chunk: &[u8], max_tail: usize) {
    tail.extend_from_slice(chunk);
    if tail.len() > max_tail * 2 {
        let drop = tail.len() - max_tail;
        tail.drain(0..drop);
    }
}
```

### C-2: `start_export` take-before-track 再構成 + stderr drain + expect 排除 (refactor)

> dead-code/構造変更ではなく released command の動作整合性のための再構成。新規 behavior の testable unit は C-1 helper でカバー済 (stderr 有界化)。take-before-track / expect 排除 / error tail 同梱は **既存 `untrack_child_after_kill_tracked_returns_none` + cargo check/test/build green** + 実機検証で担保 (#[tauri::command] が実 subprocess を spawn するため race の単体注入は不可)。

- [ ] **Step 1:** `start_export` の stdin 書込ブロック (L2918-2936) の**直後**、Job 作成ブロック (`#[cfg(windows)] let job` L2943) の**前**に、stdout/stderr take + stderr drain task を挿入:

```rust
    // #837 (P2-16) -- take stdout/stderr from the child BEFORE tracking. The old
    // code took stdout *after* track_child via
    // `guard.get_mut(&tracked_id).expect("tracked just inserted")`, which panicked
    // if a concurrent kill_tracked_processes drained the entry between track and
    // the lock (a normal cancel surfaced as an "internal error"). Taking the pipes
    // up front removes the post-track lookup entirely (mirrors start_detect).
    use tokio::io::{AsyncBufReadExt, BufReader};
    let stdout = child.stdout.take();
    let stderr = child.stderr.take();

    // #837 (P2-15) -- drain stderr into a bounded tail in parallel so a chatty
    // child can't fill the OS pipe and block (export hang), and a crash's
    // traceback survives for the error message. start_export previously piped
    // stderr but never read it (asymmetric with start_detect).
    let stderr_handle = stderr.map(|stderr| {
        tokio::spawn(async move {
            let max_tail = 2048usize;
            let mut tail: Vec<u8> = Vec::with_capacity(4096);
            let mut reader = BufReader::new(stderr);
            let mut buf: Vec<u8> = Vec::with_capacity(1024);
            loop {
                buf.clear();
                match reader.read_until(b'\n', &mut buf).await {
                    Ok(0) => break,
                    Ok(_) => append_bounded_tail(&mut tail, &buf, max_tail),
                    Err(_) => break,
                }
            }
            tail
        })
    });
```
