# 0.4.0 ロードマップ

- **日付**: 2026-09-04
- **状態**: Design（方針確定済み。issue 棚卸・再編成の実行待ち）
- **対象**: allaganeye 0.4.0 の開発計画（4 本柱）
- **前提**: 現行 `0.3.2`（2026-09-03）。L1〜L3 リリース済み、L4〜L6 未着手、L7 計画中。

## 0. 目的

0.4.x / 0.5.0 で次の 5 項目に対応する。

1. メインエージェント変更（Claude Code → Zed+DeepSeek V4 Pro）の本運用化（スキル・ルール整備）
2. **ハイライト機能の統合（L4 + L6 + L7 = 0.4.0）** — 自プレイヤーの活躍した瞬間を検出し切り抜く
3. **OBS プラグイン統合（L5 = 0.5.0）** — allaganeye の機能を OBS 上で完結させる（既存 GUI / CLI は継続サポート）
4. リポジトリ棚卸（不要ファイル・記述の削除と簡素化）
5. リグレッション防止（テストファースト・計画的な対応）

> **レイヤー番号の変遷 (2026-11-10)**: **L5（OBS プラグイン統合）** を L4 と旧 L5 の間に挿入した。これに伴い **旧 L5 → L6 / 旧 L6 → L7 / 旧 L7 → L8** に繰り下げた。本 doc は新番号で表記し、旧番号が必要な箇所は併記する。

## 1. 確定した方針（決定事項）

### 1.1 エージェント運用（項目 1）

| 項目 | 決定 |
| --- | --- |
| 主エージェント | Zed + DeepSeek V4 Pro（主運用）。Claude Code はメインではない |
| skills の正位置 | `.claude/skills/` を廃止し `.agents/skills/`（Zed 形式）に一本化（Q1.1 = C） |
| ルールファイル | `CLAUDE.md` を廃止し `AGENTS.md` を新設、Iron Law を移植。**Zed+DeepSeek が必ず読むファイル**にする。既存 `CLAUDE.md` とリンク先 doc の非陳腐化内容は `AGENTS.md` とそのリンク先に残す（ドキュメントのリグレッション禁止）（Q1.2） |
| レビュー実行経路 | Claude Code / Fable / Kimi Code は**別途セッションを起動して review**。Codex は terminal から `codex` CLI（既存 3-tier 踏襲）（Q1.3 / Q1.4） |
| Kimi Code | 別途セッション起動で利用。役割・トリガーは導入時に確定 |

> **要確認（実装時）**: Zed が project rule として自動読み込みするファイル名の正（`AGENTS.md` を project root に置いて `CLAUDE.md` を置き換えたとき Zed に認識されるか）。確定次第、`CLAUDE.md` の削除・リネームを実施する。

### 1.2 ハイライト機能の統合（L4 + L6 + L7、項目 2）

| 項目 | 決定 |
| --- | --- |
| リリース粒度 | **L4（メタデータ化）+ L6（価値評価）+ L7（自動編集）を 0.4.0 にまとめる**。GUI サポートを含める（Q2.5）。バージョンマトリクスは `docs/release-process.md` を正とする |
| 活躍の定量定義 | **キル・アシストのストリーク**を初期主信号。将来の信号追加（例: 単騎で敵アライアンスを足止めしてチーム勝利に寄与）を想定し、**拡張可能な信号モデル**にする（Q2.3） |
| 自プレイヤー識別 | プレイヤー名指定（A）を基本とし、自キャラ中央表示・キル/アシスト時の UI 発火・サウンド再生を鍵に。**ただし他のアイデアも列挙して設計で決める**（Q2.1） |
| 技術選定 | **最初から技術を決めない**。候補列挙 → 検討 → 試行 → 評価 → 採用。選定経緯をドキュメントに残す（Fanfare は過去にミックス音声で識別難で断念した経緯あり） |
| Whisper / チャット / キルログ OCR | **0.4.0 の初期信号からは除外**（2026-11-10 更新）。初期主信号は KO / ASSIST インジケータ。キルログ OCR・音声/SE・チャットは将来の拡張信号とし、#125 / #126 / #130 は `deferred` |
| clip 範囲 | イベント前後 10 秒程度を提案。**ユーザーが範囲を指定できる UI を提供**（プロセス・オチの扱い）（Q2.4） |
| 価値評価（L6） | MVP は rule-based。ML（scikit-learn）は精度検証後に追加（Q2.6） |

### 1.3 OBS プラグイン統合（L5、項目 3）

| 共通化の制約 | 設定・出力（`metadata.json` / 成果物）は GUI / CLI と同一にする。どちらを SSoT にするかを設計で決める |

- **Phase 3（L7 自動編集）**: ハイライトクリップ切り出し（前後 10 秒提案 + 範囲指定 UI / #1050）+ 投稿提案 + GUI 統合（#135）。

### Track 2.5: L5 OBS プラグイン統合（項目 3、0.5.0）

1. **方式比較**（#1107）: OBS ネイティブプラグイン（C/C++）/ OBS スクリプト（Lua・Python）/ obs-websocket 経由の外部連携 / 既存 GUI の OBS 連携強化。

4. **ハイライト連携**: L6 / L7 の成果を取り込む（Track 2 Phase 3 完了後）。
