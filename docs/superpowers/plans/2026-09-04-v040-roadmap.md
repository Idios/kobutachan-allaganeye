# 0.4.0 ロードマップ

- **日付**: 2026-09-04
- **状態**: Design（方針確定済み。issue 棚卸・再編成の実行待ち）
- **対象**: allaganeye 0.4.0 の開発計画（4 本柱）
- **前提**: 現行 `0.3.2`（2026-09-03）。L1〜L3 リリース済み、L4〜L6 未着手、L7 計画中。

## 0. 目的

0.4.x で次の 4 項目に対応する。

1. メインエージェント変更（Claude Code → Zed+DeepSeek V4 Pro）の本運用化（スキル・ルール整備）
2. L4/L5/L6 の統合（自プレイヤーの活躍した瞬間を検出し切り抜く）
3. リポジトリ棚卸（不要ファイル・記述の削除と簡素化）
4. リグレッション防止（テストファースト・計画的な対応）

## 1. 確定した方針（決定事項）

### 1.1 エージェント運用（項目 1）

| 項目 | 決定 |
| --- | --- |
| 主エージェント | Zed + DeepSeek V4 Pro（主運用）。Claude Code はメインではない |
| skills の正位置 | `.claude/skills/` を廃止し `.agents/skills/`（Zed 形式）に一本化（Q1.1 = C） |
| ルールファイル | `CLAUDE.md` を廃止し `AGENTS.md` を新設、Iron Law を移植。**Zed+DeepSeek が必ず読むファイル**にする。既存 `CLAUDE.md` とリンク先 doc の非陳腐化内容は `AGENTS.md` とそのリンク先に残す（ドキュメントのリグレッション禁止）（Q1.2） |
| レビュー実行経路 | Claude Code / Fable / Kimi Code は**別途セッションを起動して review**。Codex は terminal から `codex` CLI（既存 3-tier 踏襲）（Q1.3 / Q1.4） |
| Kimi Code | 別途セッション起動で利用。役割・トリガーは導入時に確定 |

> **要確認（実装時）**: Zed が project rule として自動読み込みするファイル名の正（`AGENTS.md` を project root に置いて `CLAUDE.md` を置き換えたとき Zed に認識されるか）。確定次第、`CLAUDE.md` の削除・リネームを実施する。

### 1.2 L4/L5/L6 統合（項目 2）

| 項目 | 決定 |
| --- | --- |
| リリース粒度 | L4/L5/L6 を 0.4.0 にまとめる。GUI サポートを含める（Q2.5） |
| 活躍の定量定義 | **キル・アシストのストリーク**を初期主信号。将来の信号追加（例: 単騎で敵アライアンスを足止めしてチーム勝利に寄与）を想定し、**拡張可能な信号モデル**にする（Q2.3） |
| 自プレイヤー識別 | プレイヤー名指定（A）を基本とし、自キャラ中央表示・キル/アシスト時の UI 発火・サウンド再生を鍵に。**ただし他のアイデアも列挙して設計で決める**（Q2.1） |
| 技術選定 | **最初から技術を決めない**。候補列挙 → 検討 → 試行 → 評価 → 採用。選定経緯をドキュメントに残す（Fanfare は過去にミックス音声で識別難で断念した経緯あり） |
| Whisper / チャット | 最初から対象外としない。必要なら採用（Q2.2） |
| clip 範囲 | イベント前後 10 秒程度を提案。**ユーザーが範囲を指定できる UI を提供**（プロセス・オチの扱い）（Q2.4） |
| L5 価値評価 | MVP は rule-based。ML（scikit-learn）は精度検証後に追加（Q2.6） |

### 1.3 リポジトリ棚卸（項目 3）

| 項目 | 決定 |
| --- | --- |
| 履歴文書の扱い | (A) 完了済みレイヤー（L1-L3）の spec は残す + 一部 (B) `docs/archive/` へ。**spec 文書の内容の棚卸まで行い、必要なものは公開用ドキュメントへ記載**（Q3.1） |
| 削除基準 | 「外部から参照されていない」を一次基準。バイナリ・同梱物・テスト fixture・CI 読込ファイルは除外。**1 PR にまとめる**（Q3.2） |
| CLAUDE.md | **存否を含め整理**（Q3.3）。§1.1 の `AGENTS.md` 新設と一体で扱う |

### 1.4 リグレッション防止（項目 4）

- 既存 CI / TDD（HARD-GATE）を維持。
- 新機能（highlight）には **GT/baseline 回帰テストを追加**（Q4.1）。
- 棚卸は削除 PR で参照断線（`scripts/check_doc_code_refs.py` 等）・CI green を実証。

## 2. 作業トラック（実行順序）

### Track 0: issue 棚卸と再編成（最優先）

1. 0.4.0 対象 issue の明確化。
2. 旧 LLM 前提 L5 issue 群の supersede、deferred ラベル外し、優先度再設定。
3. 機能単位のタスク分割 → issue 登録（漏れ防止）。

### Track 1: エージェント整備（項目 1）

1. `.claude/skills/` → `.agents/skills/` 移行（Zed 形式: `name`+`description` frontmatter）。
2. `AGENTS.md` 新設（Iron Law 移植）+ `CLAUDE.md` 廃止。
3. モデルルーティング doc / `docs/l2-workflow.md` を「DeepSeek 本運用」に更新。
4. レビュー経路（Claude Code / Codex / Fable / Kimi Code）の運用 doc 更新。

### Track 2: L4/L5/L6 設計・実装（項目 2）

- **Phase 0**: 設計 spec（活躍定量定義・信号選定・clip 仕様・自プレイヤー識別方式比較・受け入れ条件）+ **技術選定ドキュメント**（候補→検討→試行→評価→採用の経緯）。
- **Phase 1（L4 メタデータ化）**: 自プレイヤー識別 → キルログ抽出 → アシスト検出 → kill/assist イベントタイムスタンプ → イベントデータ出力フォーマット。
- **Phase 2（L5 価値評価）**: rule-based ストリークスコアリング。ML は精度検証後。
- **Phase 3（L6 自動編集）**: ハイライトクリップ切り出し（前後10秒提案 + 範囲指定 UI）+ 投稿提案 + GUI 統合。

### Track 3: リポジトリ棚卸（項目 3）

1. 未参照ファイルのリストアップ（grep 網羅）。
2. spec 内容の棚卸 → 公開 doc へ必要な内容を移行。
3. 削除 PR（1 本）+ `AGENTS.md` 簡素化。
