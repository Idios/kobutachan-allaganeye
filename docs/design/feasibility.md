# GUI Phase 0 フィージビリティ検証

実装着手前に以下の技術的不確定要素を検証し、結果を本ファイルに記録する。検証開始は [#450 GUI フレームワーク決定](https://github.com/Idios/kobutachan-allaganeye/issues/450) 確定後。

## 検証項目

### F1: MKV 再生

- **目的**: `<video>` タグ (Electron 採用時) または採用 framework のメディア API で MKV を再生可能か
- **手順**:
  1. サンプル MKV (OBS 録画、h264 + AAC、2 時間超) を採用 framework のテストハーネスで読み込む
  2. 再生・一時停止・シークが正常動作することを確認
  3. 失敗時は採用 framework のビルド設定 (codec 同梱等) を調査
- **結果**: [ ] 検証待ち

### F2: フレーム精度シーク

- **目的**: 60 fps 録画で 1 フレーム単位シークが実用速度 (目標 200 ms 以内) で可能か
- **手順**:
  1. 2:50:28 の録画で `currentTime` を 1/60s (~16.7ms) 単位で変更
  2. `requestVideoFrameCallback` によるフレーム確定までの時間を計測
  3. 代替案: Electron main で ffmpeg サムネ抽出をキャッシュ (非同期)
- **結果**: [ ] 検証待ち

### F3: 長時間ファイルの seek 耐性

- **目的**: 2 時間超のファイルで seek が破綻 (バッファロード失敗、メモリリーク、UI フリーズ) しないか
- **手順**:
  1. ランダム seek を 100 回程度連続実行
  2. メモリ使用量・フレーム落ちを計測
- **結果**: [ ] 検証待ち

### F4: 代替案のフィージビリティ (F1-F3 のいずれかが NG の場合)

- **目的**: low-res proxy ファイル (480p h264) の事前生成で UX を成立させられるか
- **手順**:
  1. `allaganeye detect` 完了時に proxy を並行生成するフローを試作
  2. proxy 生成時間を計測 (2 時間録画で 5 分以内が目標)
  3. 書き出し時は元動画を使用する分岐を確認
- **結果**: [ ] 検証待ち (F1-F3 が OK なら不要)

### F5: ffmpeg sidecar / subprocess の同梱配布

- **目的**: L2b (#106) インストーラ形式と整合して ffmpeg バイナリを同梱できるか
- **手順**:
  1. 採用 framework + 採用インストーラ形式 ([#452](https://github.com/Idios/kobutachan-allaganeye/issues/452)) で ffmpeg.exe 同梱を試作
  2. Windows Defender SmartScreen の警告レベルを確認 (コードサイニング未実施時)
- **結果**: [ ] 検証待ち

- [ ] F1 OK または F4 代替案で MKV 再生が成立
