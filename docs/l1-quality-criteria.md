# L1 リリース品質基準

L1（試合分割）のリリース判定に使用する品質基準を定義する。

## 基準環境

処理速度の目標値は以下の環境で測定する。

- **CPU**: AMD Ryzen 9 9950X3D (16C/32T)
- **GPU**: NVIDIA GeForce RTX 5090
- **ストレージ**: SSD (NVMe)
- **OS**: Windows 11
- **ffmpeg**: 8.1 以上

## 1. 検知精度（GPU/CPU 共通）

検知精度の目標はモード（GPU/CPU）に関わらず共通。Pass 1 の実装が異なるだけで Pass 2 以降は共通パスのため、結果は同一であるべき。

### 必達ライン

| 指標 | 目標 | 根拠 |
|---|---|---|
| 試合検出率（recall） | ≥ 85%（手持ち全録画平均） | 10 試合中 1-2 の見逃しは L1 として許容。L2 GUI で補完可能 |
| 誤検出率（precision） | ≥ 90% | 10 件中 1 件の偽陽性まで。手動削除が現実的な頻度 |
| 境界精度 | ±10s | `-c copy` のキーフレーム制約（キーフレーム間隔 2-10s）を含む。視聴時に許容できる範囲 |

### ストレッチゴール

| 指標 | 目標 |
|---|---|
| 試合検出率（recall） | ≥ 95% |
| 誤検出率（precision） | ≥ 95% |
| 境界精度 | ±5s |

### GPU/CPU 結果一致性

| 指標 | 必達 | ストレッチ |
|---|---|---|
| match 数の差異 | ±1 以内 | 完全一致 |
| 境界タイムスタンプの差異 | ±10s 以内 | 完全一致 |

### 測定方法

- テストデータセット（§5）の全録画で測定する
- recall = （正しく検出された試合数）/（手動分割による真の試合数）
- precision = （正しく検出された試合数）/（検出された全 match 数）
- 境界精度 = 各試合の開始/終了タイムスタンプと手動分割位置の差の最大値

## 2. 検知処理速度

### CPU モード（non-GPU）— 必達ライン

| 指標 | 目標 | 根拠 |
|---|---|---|
| 処理時間 | 録画時間の 10% 以内 | 2h 録画 → 12 分以内。現状 5.9%（7m12s / 121.7min）で達成済み |

### CPU モード — ストレッチゴール

| 指標 | 目標 |
|---|---|
| 処理時間 | 録画時間の 5% 以内 |

### GPU モード — 推奨ライン

GPU は環境差（VRAM 容量、ドライババージョン、コーデック対応状況）が大きく、絶対値での目標設定が困難。相対指標で定義する。

| 指標 | 目標 | 根拠 |
|---|---|---|
| 処理時間 | CPU モードの 1.5 倍以内 | AV1 では GPU 効果が薄い。H.264 では CPU より高速になることを期待 |
| フォールバック | GPU 利用不可時、自動で CPU モードに切替 | 現行実装で対応済み |

## 3. 分割処理速度（GPU/CPU 共通）

`-c copy` による無劣化分割はモードに依存しない（検知後の処理）。

| 指標 | 目標 | 根拠 |
|---|---|---|
| 処理時間 | 入力サイズ 1GB あたり 10 秒以内 | 現状数秒〜数十秒で完了。ボトルネックにならない |

## 4. 分割品質

| 観点 | 基準 |
|---|---|
| 再生可能性 | 出力 MP4 が標準的なメディアプレイヤー（Windows Media Player, mpv, VLC 等）で正常に再生できること |
| コーデック保持 | 入力動画の映像コーデック・音声コーデックが出力に保持されること |
| メタデータ | `metadata.json` に各 match の開始/終了タイムスタンプ、duration が記録されること |

## 5. テストデータセット

手持ちの録画データで測定する。追加取得は不要。

| 録画 | 時間 | 手動分割 match 数 | 用途 |
|---|---|---|---|
| 2026-01-16 | 121.7 min | 7 | ベースライン（primary） |
| 2026-01-18 | 137.2 min | 11 | ベースライン |
| 2026-01-19 | 153.9 min | 10 | ベースライン |
| 2026-04-08 | — | 8 | 音声テスト用。scorebar 残像問題の再現録画 |

ベースライン 3 録画は `tests/baselines/` に境界タイムスタンプが記録されており、退行テストに使用。

## 6. 対応入力形式

| 観点 | 対応範囲 |
|---|---|
| コンテナ | MP4, MKV, AVI, MOV |
| 映像コーデック | H.264, H.265 (HEVC), VP9, AV1 |
| 解像度 | 1080p（動作確認済み）。1440p / 4K は未検証だが scorebar ROI が解像度に応じてスケールするため対応見込み |
| フレームレート | ≥ 24 fps |

## 7. エラーハンドリング

不正な入力や環境の問題に対して、適切な exit code とエラーメッセージを返すこと。

| 状況 | 期待する exit code | 期待する挙動 |
|---|---|---|
| 入力ファイルが存在しない / 未対応形式 | 2 | 原因を示すエラーメッセージ |
| ffmpeg / ffprobe が見つからない | 3 | インストール手順を案内するメッセージ |
| 試合境界が 1 つも見つからない | 4 | 閾値調整のヒントを含むメッセージ |
| 設定値が範囲外 | 5 | 有効な範囲を示すメッセージ |

## 8. 再現性

| 観点 | 基準 |
|---|---|
| 決定的出力 | `--no-cache` 指定時、同一入力に対して同一の分割結果（match 数・境界タイムスタンプ）が得られること |
| キャッシュ整合性 | キャッシュあり/なしで最終的な分割結果が同一であること |

## 9. ユーザー体験

| 観点 | 基準 |
|---|---|
| 進捗表示 | デフォルトで検知進捗（Pass 1/2 のフレーム数）と分割進捗を表示すること |
| `--quiet` モード | 出力ファイルパスのみを表示すること（スクリプト連携用） |
| エラーメッセージ | 原因と対処法を示す日本語または英語のメッセージ |

## 10. 静的解析

`docs/roles/protocol.md` §「コード品質ゲート」に準じる。

| ツール | 基準 |
|---|---|
| ruff check | エラー 0 件 |
| ruff format | 差分 0 件 |
| pyright | エラー 0 件 |
| pytest | 全テスト pass（`slow` マーカー除外） |

## リリース判定

上記 §1〜§10 の**必達ライン**をすべて満たした時点で L1 リリース可能と判断する。ストレッチゴールは将来バージョン（パッチリリース）で達成を目指す。

リリース判定の実施者はディレクターとし、テストデータセット（§5）での実測値を `docs/benchmarks.md` に記録した上で判断する。
