# バグ報告ガイド

Allagan Eye にバグ報告をいただく際の手順です。動画ファイル添付時のプライバシー配慮と、メンテナ側の対応フローを明記しています。

本ガイドの対象読者: Idios 以外の外部ユーザー (バグ報告者)。

## §1 バグ報告前の確認

以下を事前に確認いただくと、調査が迅速に進みます。

### 1.1 既存 issue の検索

同じ / 類似のバグがすでに報告されていないか確認してください。

- [Open issues](https://github.com/Idios/kobutachan-allaganeye/issues?q=is%3Aissue+is%3Aopen)
- [Closed issues](https://github.com/Idios/kobutachan-allaganeye/issues?q=is%3Aissue+is%3Aclosed) (解決済み・仕様として確定済みの場合あり)

既存 issue がある場合は、新規作成ではなく既存 issue へのコメント追加で情報を寄せてください。

### 1.2 再現手順の整理

可能な限り「最小再現手順」の形に整理してください。

- どの動画を入力したか (長さ・解像度・fps・コーデック)
- どの CLI コマンド・オプションで実行したか
- 何度実行しても同じ結果になるか (間欠的か常に再現するか)

### 1.3 環境情報の収集

`allaganeye split <video> -v` の出力ヘッダには OS・Python・ffmpeg・CPU・GPU・メモリ情報が含まれます (#336)。これを issue 本文の環境欄に貼り付けてください。

```
allaganeye 0.2.0 (ffmpeg 8.1, Python 3.12.10, Windows 11)
  CPU: AMD Ryzen 9 9950X3D (16C/32T)
  GPU: NVIDIA GeForce RTX 5090 (32GB VRAM)
  Memory: 61.6 GB
  Disk: 1359.5 / 3726.0 GB free on E:
```

ヘッダ収集が難しい場合は `allaganeye --version` だけでも記載してください。

### 1.4 ログの取得

バグの内容によっては以下のログ出力が調査の助けになります。

- **エラー発生時**: `-v` / `--verbose` を付けて再実行し、traceback を含む詳細出力を取得
- **検知 (暗転判定) 関連のバグ**: `allaganeye debug-brightness <video> > brightness.csv` で輝度 CSV を取得し、圧縮して添付 (動画本体よりサイズが小さく、個人情報も含まれない)

## §2 動画添付時の注意

バグ再現のため動画ファイルの添付をお願いする場合があります。添付前に以下を確認してください。

### 2.1 個人情報・機密情報の確認

#### 公開される範囲

GitHub issue への添付は**公開リポジトリへのアップロード**を意味します。一度アップロードされたファイルは、後から delete しても GitHub の CDN キャッシュや Internet Archive などから取得される可能性があります。

#### 含まれうる個人情報

| 種別 | 例 | 推奨対応 |
|---|---|---|
| 他プレイヤーの情報 | プレイヤー名、ワールド、パーティ情報、FC 名 | ぼかし / モザイク / クロップ |
| 自分のアカウント情報 | キャラクター名 (公開可否は自己判断) | 判断は報告者に委ねる |
| 機密情報 | メールアドレス、決済情報、ウィンドウ上の別アプリ | **必ず除去** |
| 位置情報 | デスクトップに映った地名 / IP アドレス表示 | **必ず除去** |

#### プレイヤー名ぼかし

現状は手動で対応いただく必要があります (OBS のクロップ、動画編集ソフトでのモザイク処理等)。将来的にレイヤー L6 で allaganeye 本体にぼかし機能を追加予定です。

### 2.2 動画サイズ

GitHub の 1 ファイル upload 上限は 25 MB (issue 添付) または 100 MB (git push) です。

- 最小再現動画 (問題箇所前後 10-30 秒のクロップ) を推奨
- 25 MB を超える場合は外部ストレージ (Google Drive / Dropbox) のリンクを issue に貼る

### 2.3 添付を避けるべき動画

以下の場合は動画添付を**しないでください**:

- 他プレイヤーの顔がキャプチャに映っている (顔認識回避のため)
- 商用放送・配信の録画
- 第三者 (FC メンバー等) の同意を得ていない動画

## §3 Issue 作成手順

### 3.1 テンプレートの使用

[New issue ページ](https://github.com/Idios/kobutachan-allaganeye/issues/new/choose) から「[bug] バグ報告」テンプレートを選択してください。

テンプレートには以下の項目があります:

| 項目 | 必須 | 内容 |
|---|---|---|
| 再現手順 | 必須 | §1.2 で整理した最小再現手順 |
| 期待される動作 | 必須 | どうなるべきか |
| 実際の動作 | 必須 | 何が起きたか (エラーメッセージ全文含む) |
| 環境情報 | 任意 | §1.3 のヘッダ出力 |
| 同意 checkbox (2 件) | 必須 | §3.2 参照 |

### 3.2 同意 checkbox の意味

Issue Template には同意 checkbox が 2 件あります (両方 required)。**動画を添付しない報告でも必ずチェック**してください (将来動画を添付する可能性への同意として)。

| checkbox | 意味 |
|---|---|
| 他プレイヤー個人情報の確認 | 添付する場合、他プレイヤーのプレイヤー名・ID・パーティ情報について適切に処理 (ぼかし / クロップ / 公開可) 済みであること |
| FF14 機密情報の確認 | 添付する場合、アカウント情報・決済情報・その他機密情報が含まれていないこと |

報告者が事前に `allaganeye-guard verify` を実行する必要は**ありません**。セキュリティ検査はメンテナ側で実施します (§4.2 参照)。

## §4 対応プロセス

### 4.1 メンテナ側の受領後フロー

メンテナ (= Claude Code セッションで動くアシスタント + 人間メンテナ Idios の両方) が外部からの動画を扱う際の標準手順です。

1. Issue 内容確認 (再現手順・環境情報)
2. 動画添付があればダウンロードし、隔離ディレクトリに保存
3. **エージェントが `allaganeye-guard verify <file>` を実行** (受領動画は必ず検査してから allaganeye で処理)
4. PASS (exit 0 / 1) なら調査開始
5. FAIL (exit 2) なら §4.3 の差戻しフローへ
6. ERROR / 入力エラー (exit 3 / 4) ならメンテナ環境側の問題として調整
7. 調査完了後、ローカル動画を削除し issue に結果コメント

詳細は [docs/guard-integration.md](guard-integration.md) §6 参照。

### 4.2 検査結果の通知

メンテナは issue に以下のコメントを残します:

- **PASS**: `allaganeye-guard verify` の exit code と主要フェーズの PASS を記録 (報告者への安心材料)
- **PASS with warnings (exit 1)**: warning 内容を記録、そのまま調査続行
- **FAIL (exit 2)**: FAIL した Phase と脅威 ID (T1-T8) を記録、§4.3 の差戻しへ
- **ERROR (exit 3)**: メンテナ環境側で解決 (guard の依存ツール更新等)

### 4.3 FAIL 時の差戻しフロー

セキュリティ検査で FAIL が出た場合:

1. メンテナが FAIL 理由 (コンテナ不正・マルウェアシグネチャ等) を issue にコメント
2. 提供者に以下のいずれかを依頼:
   - リエンコード (FFmpeg で `-c copy -f matroska output.mkv` 等) して再提出
   - 別の録画データで再試行
   - 最小再現の手順を文章のみで説明 (動画添付なし)
3. 代替情報 (ログ / CSV / スクリーンショット) のみでの調査を試みる

**FAIL 動画は allaganeye で処理しません**。メンテナ側で破棄します。

### 4.4 調査完了時

- 原因が特定されコード修正に至った場合: 修正 PR を作成 (issue 本体は手動クローズ)
- 仕様として意図した動作の場合: 説明コメントを残し、必要なら docs に反映
- 再現できなかった場合: 情報追加を依頼、またはクローズ

いずれの場合も、ダウンロードした動画はメンテナ側で削除します (提供者同意に基づく)。
